**Mutation interface:** add `rescheduleConfirmedBooking(client: PoolClient, actor: BookingActor, input: {bookingId:string; dropoffDate:string; dropoffTime:string; idempotencyKey:string}): Promise<BookingReservationResult>` and `cancelConfirmedBooking(client: PoolClient, actor: BookingActor, input: {bookingId:string; idempotencyKey:string; reason:string}): Promise<{status:'cancelled'|'replayed'; bookingId:string} | {status:'forbidden'|'invalid'; code:string}>` in `booking-service.ts`. Caller owns the transaction; validate actor/branch, current booking state and idempotency payload, lock the existing booking, lock every affected branch/date/bay occupancy key in stable lexicographic order, and re-read configuration under compatible locks/version check before capacity validation and writes.
