# Phase 1 Commercial Workstream Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development, the user-selected execution method, when implementation is explicitly authorized after plan review. Steps use checkbox syntax. This document authorizes no implementation, database write, commit, publication, or policy activation.

**Goal:** Preserve each customer agreement from vehicle-specific enquiry through accepted quotation, deferred installation, coverage, benefits, transport and truthful owner reporting.

**Architecture:** Extend the existing React/Vite, Express, PostgreSQL and `@garage/domain` boundaries. One booking service owns capacity; one warranty issuance service owns manual and automatic issuance; one finance service owns money calculations; the operations workstream owns shared action queues, report presentation and guided forms. Commercial services expose persisted records to those consumers rather than recreating them.

**Tech Stack:** Existing TypeScript, React, Express, PostgreSQL, Clerk, Zod and Vitest; browser harness supplied by the foundation/operations workstream.

**Spec:** [accepted direction](../../product/PRODUCT_DIRECTION_AND_RELEASES.md), [entire Phase 1 tracker](../../testing/PHASE_1_ISSUES_TRACKER.md), [handover](../../operations/PHASE_1_FULL_PLAN_HANDOVER.md), [facts](../../product/GO_STORES_FACTS_2026-11-16.md), [dossier](../../product/GO_STORES_MEETING_DOSSIER_2026-11-16.md), [workflow research](../../product/WORKFLOW_PRODUCT_RESEARCH_2026-11-16.md), [PRD](../../product/PRD.md), [data model](../../engineering/DATA_MODEL.md), [architecture](../../engineering/ARCHITECTURE.md), [security](../../engineering/SECURITY_PRIVACY.md), [private evidence](../../engineering/WARRANTY_EVIDENCE_STORAGE.md).

## Global constraints

- Feature scope is accepted; advertised prices, operating calendars, lifetime wording, deposits, eligibility and financial recognition remain unapproved business parameters.
- Preserve Arabic/RTL and English/LTR, actual server authorization and branch scope, Replit entry points/port and `@garage/domain` import boundaries.
- Never infer account privileges from social profiles. Central-inbox membership alone grants no finance, policy-publication, claim-decision or unrelated workshop authority.
- Preserve existing issued terms and dates. No global reseed, destructive historical rewrite or inferred customer acceptance.
- Keep public QR verification Owner-gated, private evidence private, and operational/demo datasets and provider effects isolated by the foundation workstream's execution context.
- Money uses integer minor units and explicit currency for new records. Existing decimal draft invoices retain their semantics until explicitly reconciled; they are not payments, revenue or profit.
- No commits are requested. Implementation checkpoints name reviewed files, tests and outstanding decisions without staging or committing unless subsequently authorized.

## Review focus

1. A later installation must not silently acquire today's offer or warranty terms: C03/C05/C07 test retirement and revised catalogue after acceptance.
2. A bundle can count workshop work, payment and benefits twice: C04/C09/C12 test stable component/source identities and one physical intake/job.
3. Back navigation, stale tabs and unknown commit outcomes can duplicate an acceptance or redemption: C03/C08/C09/C10 test idempotency, version conflicts and recovery.
4. Lifetime does not mean unconditional or immortal: C06/C07 test missing definition, recorded termination, unknown eligibility and human claim review.
5. Cross-branch central agents, private card evidence and demo fixtures can leak through reports: C10/C11/C12/C13 test field-level projections, RBAC and dataset exclusion.

## Shared contracts and ownership

All IDs below are opaque strings. `DateOnly` below is a documentation alias for the validated `YYYY-MM-DD` string returned by O01 `dateOnlyFromSql(value: string): string`, not a competing parser or timestamp type. Timestamps are UTC ISO strings. `ExecutionContext = { mode: 'operational' | 'scenario'; environmentId: string }` is a server-only startup value established by the foundation database/environment marker check. The two modes use separate databases, deployments and secrets. No HTTP parameter can choose a dataset, connection string or execution context; a scenario identity cannot open operational data. Services taking `context` receive this trusted startup value, and still resolve actor/branch authorization. Functions whose canonical interface omits `context` bind that same server repository on initialization.

Operations owns `ReportFilter = { branchId: string | 'all'; from: string; to: string; groupBy: 'day' | 'week' | 'month' }` in `packages/domain/src/reporting.ts`; valid dates are inclusive calendar boundaries converted using the configured reporting timezone. C08 owns warranty-specific reducers while O13 owns generic guided-step interaction and `reconcileBookingDraft(previous, next)`; do not create a second wizard framework.

Stable error envelope remains the inspected existing `routeError` response `{ code, message }` (`warranty/warranties.ts:85`), not a new nested envelope. Use 400 invalid shape, 403 unauthorized action, non-enumerating 404 inaccessible record, 409 stale revision/already consumed/capacity conflict, and 422 `POLICY_UNCONFIGURED` with authorized missing-field guidance. Idempotent mutation keys are scoped by server environment, actor, action and entity, with request hash; same key/different body returns 409, same committed request returns its original result. Cross-service transaction lock order is promotion pool → qualification evidence → allocation → commercial reservation → booking/job → lexicographically sorted resource/date/bay keys. Read identifiers without locking first, acquire in that order, and revalidate relations/revisions after locks; cancellation, rescheduling and reversal must use the same order. A direct booking with no commercial links skips those locks rather than acquiring them later.
