# Review A - Owner, 1280 px, EN + AR

Scope note: I opened the overview and first slices (about 1000 px) of the pages listed below. Not every slice of the very tall pages (quotes 35k, warranties 27k, overview 13k, bookings-transport 8.8k) was viewed; lower regions were judged from the overview thumbnail only. Pages with a full view of the first screen in both locales: overview, whatsapp, workshop, customers, finance (AR+EN). EN only: quotes, warranties, catalogue, settings, quotes-reservations, quotes-benefits, quotes-promotions, bookings-transport, settings-access. AR not opened for the EN-only pages (assumed structurally identical, not verified). `bookings` (EN) was captured while still "Loading page..." (see A-04). Paths below are relative to `checks/screenshots/`.

## Verdict
The shell (dark sidebar, warm off-white cards, teal accent) is calm and coherent, and finance, customers, settings and catalogue read well. The product is let down by three systemic problems: (1) KPI money values overflow their tiles on the Overview page in both locales (P1); (2) every list is an unpaginated full dump (191 to 757 to 661 rows, 12k-35k px pages), so the tool is not scannable; (3) the same concept is built in different ways per page (page-title position, "Add" buttons, tab bars, Arabic names bolded vs not, plates in different bidi treatments). Seeded data adds noise (mixed AR/EN names in one row, duplicate rows, "(example)" in titles, "DEMO A17" plates).

## Arabic / RTL summary
Layout mirroring is correct (sidebar right, text right, tab order). Problems are in bidi strings: phone numbers (+20 shifts to the end), negative amounts and percents on Finance, "ج.م." placement on Overview tiles (breaks out of card), plate letters in mixed rows, date strings inside transport rows. Inbox bubbles and times are fine. AR fonts: Arabic body looks lighter/larger than EN and needs its own line-height token; headings use the same weight but the page title reads bigger than EN.

## What would make this noticeably better
1. One shared DataTable (paging, sticky header, column presets, density toggle, row-click, empty/loading/error states) and apply to Overview, Quotes, Warranties, Transport, Benefits, Customers.
2. An owner dashboard that answers "how are we doing today": 4 money KPIs with period + trend, today's drop-offs, ready for pickup, aged jobs, overdue quote follow-ups, branch comparison - then a short "needs attention" list, not 191 rows.
3. Number/currency/plate/phone/date formatting utilities (`<Money>`, `<Plate>`, `<Phone>`, `<DateText>`) with bidi isolation and tabular numerals; ban raw string concatenation.
4. Design tokens for type scale, control height (40 px), radius, spacing; lint hard-coded font sizes.
5. A single PageHeader + FilterBar + Tabs component and one topbar user menu.
6. Workshop board: wider cards, wrap-safe footers, overdue/age indicators, assigned technician avatar, column scroll with counts.
7. Cleaner seed data (one language per locale, no duplicates, realistic status spread) so screenshots represent the product.
8. Make unfinished areas intentional: Promotions tab, "Not available yet" settings, Staff read-only state.
9. Accessibility pass: contrast token, min text size, visible focus rings, `aria-sort` on sortable headers, labelled icon buttons (refresh, arrow icons on KPIs).
