# Review D - Branch manager (Salma Nabil, Nasr City Service Center)

Scope: 72 screenshots (en/ar x 1280/768/360 x 12 pages). Viewed in depth: all 12 en/1280 pages (first 1000-1400 px, plus overviews), en/768 bookings and quotes, en/360 overview and bookings, ar/1280 overview. Remaining ar and 768/360 pages checked by size and structure only (see "Not individually inspected").

## Verdict

The manager view is functionally almost identical to the owner view, and that is the main finding: it does not feel like a branch-manager product. It shows the same nav, the same 415-row bookings table and the same 157-row "Needs attention" list, scoped to one branch but with no summarising layer. The biggest problems are (1) a 157-row overview that buries four KPIs under an undifferentiated wall of rows, (2) tables that horizontally clip or crush columns at 768 (screenshots are 863-1009 px wide, i.e. page overflow), (3) a clipped "Confirm" button at 1280, (4) cramped workshop cards, and (5) heavy bidi/Arabic-in-English-UI mixing from seed data. Visual style (tokens, tabs, badges) is generally coherent at 1280.

## Recommendations beyond bug fixing

1. Design a real manager home: today's drop-offs/pickups timeline, technician load (who is idle / overloaded), unassigned jobs with one-click assign, SLA risk, and pending confirmations with inline Confirm. Replace the flat 157-row list.
2. Introduce paging + saved filters + sticky header on every table; consider a virtualised list for the 400+ row pages.
3. Create one shared PageHeader + Toolbar + Plate + Money + DateTime set of primitives and migrate every page; this alone resolves D-07, D-08, D-06, D-29, D-35.
4. At 768 adopt the 360 card layout until ~1000 px; the card layout works well already.
5. Make restricted areas explicit: if a capability is missing show a lock + tooltip, not silence; add a "Your branch" scope chip.
6. Localise seed data per locale (Arabic names only in ar, English in en, or consistently bilingual with `<bdi>`), remove "(example)" strings, and avoid "000" phone numbers.
7. Accessibility pass: contrast tokens for muted text and badges, 12 px minimum, visible focus ring, accessible names for icon-only buttons (refresh in Inbox, KPI arrows).
8. Add a bottom-nav safe-area padding and test full-page capture with the fixed nav hidden so screenshots stay readable.
