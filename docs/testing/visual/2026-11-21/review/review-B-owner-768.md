# Review B - Owner, 768 px (tablet), EN + AR

Method: all 30 captures (15 pages x 2 locales) were overviewed. Slices were read for overview, quotes, reservations, benefits, bookings-transport, warranties, whatsapp, customers, workshop, finance and catalogue in EN, and for overview in AR. The remaining AR pages and the bookings, promotions, settings and settings-access pages were not opened as slices; I judged them from the overview thumbnails, their size and their structure, and from the EN/AR parity noted below. Sizes were measured from the PNGs.

## Verdict
At 768 px the app is neither a tablet layout nor a mobile layout. The breakpoint that hides the sidebar is `max-width: 760px` (`shared/styles/layout.css:124`), so 768 keeps a fixed 220 px sidebar and leaves about 548 px of content. That is cramped for the desktop-oriented tables. Result: headings and cells wrap letter by letter ("Boo/kin/g/revi/ew", "Handove/r/inspectio/n"), the topbar stacks into three crowded rows, and several pages are wider than the viewport. In these captures five pages are still wider than 768 px, so the overflow reported in the run is still visible (it may predate the CSS patch; re-capture before concluding). Several pages (quotes, warranties, overview, bookings-transport) are tens of thousands of px tall with no paging.

Capture widths (768 = OK): quotes 1019 (EN) / 965 (AR), bookings-transport 1009 / 996, quotes-reservations 925 / 911, quotes-benefits 870 / 838, whatsapp 780 / 776. All other pages are 768.

Page heights: warranties 59238 / 73194 px, quotes 35619 / 37027 px, overview 25885 / 29937 px, bookings-transport 14759 / 12790 px. In practice these are unusable without paging.

## EN vs AR
Structure is identical. The mirroring is correct (sidebar right, search icon right, tabs mirrored). AR issues: money amounts with the currency suffix "ج.م." break over the left edge of the card (B-4), the Arabic digit/Latin digit mix (Latin digits used in amounts, dates and plates, good, but the page title "11,805,270.40 ج.م." puts the suffix on the wrong visual side), and tall rows from Arabic line-height in table cells ("مراجعة الحجز" breaking per letter). Warranties is about 14k px longer in AR.

## Tap targets
Not enough clearance on 768: language switch buttons (about 30 px high), tab links (about 34 px), whatsapp action buttons (about 34 px), the "/" shortcut chip in search, the "find" button. Aim for 40-44 px on touch widths.

## What would make this noticeably better
1. Adopt a real tablet layout: collapsible icon rail at <=1024, bottom nav at <=760, content max width centred at wider sizes.
2. Move every list page to a "table at >=1100, cards below" rule through the existing `data-cards` mode (`DataTable.tsx`) instead of relying on horizontal scroll; the wide pages are exactly the ones that did not opt into cards.
3. Add paging (or "load more") to all lists and show counts; add sticky table headers.
4. Fix money display: one `Money` component with size variants, `bdi`/`dir=ltr`, nowrap, and a compact format on KPIs.
5. Slim the topbar to a single 48-56 px row and move sign-out and the e-mail into the user menu.
6. Define typography tokens and one shared page header, filter bar and tab bar, and remove per-page variations.
7. Clean the seed data: duplicate rows, "(example)" in titles, mixed Arabic/English names per row, and "-" placeholders; make demo data match the locale of the current UI where possible.
8. Add visual regression assertions for `document.documentElement.scrollWidth <= innerWidth` at 768 on all pages so the overflow does not return.
